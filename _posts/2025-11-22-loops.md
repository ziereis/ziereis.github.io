The following displays how one could rediscover the `im2col` transformation for convolutions by playing with loop fusion/fission.

## matmul is a fused operation

Consider this pseudocode of a matmul
```
def matmul(A: tensor<MxK>, B: tensor<KxN>, C: tensor<MxN>)
  for m in M
    for n in N
      for k in K
        C[m,n] += A[m,k] * B[k,n]
```

What fundamental operations are actually performed here?

- multiplication `A[m,k] * B[k,n]`
- add reduction `C[m,n] += ...` of dimension `K`

From first glance you might think that's it but there is more to it. Since there are three loops and `A` and `B` are only accessed from two of the loop iterators it means both tensors are what's mostly referred to as "broadcasted". Which means they are repeated across some dimension. `A` is repeated across dimension `N` and `B` is repeated across dimension `M`. Now of course they do not really "exist" repeated here, they are only accessed repeatedly, but this is really only a result of fusing the broadcast of `A` and `B` with another operation.

So there are two more "fundamental" operations performed here:

- broadcast of `A` across dimension `N`
- broadcast of `B` across dimension `M`

To see why this is true we can also implement the matmul with only using these operations:

```
def matmul(A: tensor<MxK>, B: tensor<KxN>, C: tensor<MxN>)
  # broadcast A
  t1: tensor<MxKxN>
  for m in M
    for n in N
      for k in K
        t1[m,k,n] = A[m,k]
  # broadcast B
  t2: tensor<MxKxN>
  for m in M
    for n in N
      for k in K
        t2[m,k,n] = B[k,n]

  # multiply the broadcasted A and B
  t3: tensor<MxKxN>
  for m in M
    for n in N
      for k in K
        t3[m,k,n] = t1[m,k,n] * t2[m,k,n]
  # reduce across K
  for m in M
    for n in N
       for k in K
         C[m,n] += t3[m,k,n]
```

The result of this computation is the same as for our original implementation, don't believe me? try this:

```python
import numpy as np

A = np.random.rand(10, 10)
B = np.random.rand(10, 10)

C = np.matmul(A, B)

t1 = A[:, :, None]
t2 = B[None, :, :]
t3 = t1 * t2
C_ = np.sum(t3, axis=1)
print(np.allclose(C, C_))
```


You could also convert this back into the original implementation by applying basic loop fusion. Now the question is: Why would one ever want to do this?

Firstly by understanding the properties of what we just did here should make it pretty easy to understand how to expand the same logic to derive arbitrary other fused kernels, like matmul + activation ...

Secondly it's widely known that fusing operations is not always a net gain in terms of performance. While we can accept for a matmul it probably never makes sense to do the computation like displayed above, there are many other operations where it might make sense to do so.


# from loop fission to im2col
Consider the following pseudocode of a standard conv2d.

```
def conv2d(I: tensor<iC,iH,iW>, O: tensor<oC,oH,oW>, K: tensor<oC,iC,kH,kW>)
  for k in oC:
    for i in oH:
      for j in oW:
        for c in iC:
          for u in kH:
            for v in kW:
              O[k, i, j] += I[c, i+u, j+v] * K[k, c, u, v]
```

Similar as before lets list out the "fundamental" operations:

- multiplication `I[c, i+u, j+v] * W[k, c, u, v]`
- add reduction ` O[k, i, j] +=  ...` in contrary to the matmul there are multiple dimensions reduced here `(iC, kH, kW)`
- broadcast of `K[k, c, u, v]` by `oH` and `oW`
- broadcast of `I[c, i+u, j+v]` by `oC`
- sliding window of `I[c, i+u, j+v]` (this is a weird one, just treat it as special kind of "broadcast")

we could fully decompose this into its individual operations as we did it for the matmul, however since this is a lot to write we will cheat a little bit by Googling what the im2col transformation actually does:


`It achieves this by extracting overlapping "windows" from the input, flattening each window into a column, and then stacking these columns to form a larger matrix.`

Using this information and reading the name "image"2col we can be pretty sure that the transformation most likely only touches the `I` matrix of the kernel so let's only perform fission on the operations that touch the `I` matrix, namely the broadcast and the sliding window.

```
// sliding window of I
t1 = tensor<oH,oW,iC,kH,kW>
for i in oH
  for j in oW
    for c in iC
      for u in kH
        for v in kW
          t2[i,j,c,u,v] = t1[c,i+u, j+v]

// broadcast of I by oC
t2 = tensor<oC,oH,oW,iC,kW,kW>
for k in oC
  for i in oH:
    for j in oW:
      for c in iC
        for u in kH
          for v in kW
            t1[k,i,j,c,u,v] = t1[i,j,c,u,v]


for k in oC
  for i in oH
    for j in oW
      for c in iC
        for u in kH
          for v in kW
            O[k,i,j] += t2[k,i,j,c,u,v] * K[k,c,u,v]
```

Here the broadcast of `I` looks like an operation you would never want to have unfused so let's fuse this as well with the last loop.

```
// sliding window of I
t1 = tensor<oH,oW,iC,kH,kW>
for i in oH
  for j in oW
    for c in iC
      for u in kH
        for v in kW
          t1[k,i,j,c,u,v] = I[k,c,i+u, j+v]

for k in oC
  for i in oH
    for j in oW
      for c in iC
        for u in kH
          for v in kW
            O[k,i,j] += t1[i,j,c,u,v] * K[k,c,u,v]
```

What is now noticeable in he second loop is that it has a bunch of loops that could be easily collapsed. For example
the loops over (`iC`, `kH`, `kW`) and (`oH`, `oW`). 

By collapsing loops i'm talking about the following transformation:

```
A -> tensor<M,N>
B -> tensor<M,N>
for i in M
  for j in N
    C[i,j] = A[i,j] <op> B[i,j]

is equal to ->

K = M * N
A_ = A.view(K)
B_ = B.view(K)
C_ = C.view(K)
for i in K
  C[i] = A[i] <op> B[i]
```

So let's collapse the loops:

```
// sliding window of I
t1 = tensor<oH,oW,iC,kH,kW>
for i in oH
  for j in oW
    for c in iC
      for u in kH
        for v in kW
          t2[k,i,j,c,u,v] = t1[k,c,i+u, j+v]
R = iC * kW * kH
S = oH*oW
t2 = t1.view(S,R)
t3 = K.view(oC,R)
t4 = O.view(oC,S)

for k in oC
  for s in S
    for r in R
      t4[k,s] += t2[s,r] * K[k,r]

O = t4.view(oC,oH,oW)
```

Now the only thing missing to make the second loopnest a canonical matrix multiplication is transposing the `K` matrix, however most libraries would actually prefer K laid out in a transposed format as this makes data access consecutive and thus faster (at least on CPUs).

The final result you are seeing here is exactly what the im2col transformation is expressed only by performing a couple of transformations on our input. If executing this is actually faster than performing a canonical conv2d or applying different transforms like Winograd highly depends on the shape of the inputs. This is also easy to see since we are clearly using more memory and performing an operation on a "larger" amount of data since we don't fuse the sliding window operation. Concretely we need an extra allocation of `tensor<oH,oW,iC,kH,kW>` instead of `tensor<oH,oW,iC>` for our input, so if `kH` and `kW` are not too large, it's probably worth doing it.

What I really wanted to demonstrate here is how one can derive a "specialized" algorithm through a series of basic loop transformations. 

Try it yourself:

```python
import numpy as np

def conv2d(I: np.ndarray, K: np.ndarray):
  iC, iH, iW = I.shape
  oC, _, kH, kW = K.shape
  oH, oW = iH - kH + 1, iW - kW + 1
  O = np.zeros((oC, oH, oW))
  for k in range(oC):
    for i in range(oH):
      for j in range(oW):
        for c in range(iC):
          for u in range(kH):
            for v in range(kW):
              O[k,i,j] += I[c,i+u,j+v] * K[k,c,u,v]
  return O

def conv2d_im2col(I: np.ndarray, K: np.ndarray):
  iC, iH, iW = I.shape
  oC, _, kH, kW = K.shape
  oH, oW = iH - kH + 1, iW - kW + 1
  t1 = np.zeros((oH, oW, iC, kH, kW))
  for i in range(oH):
    for j in range(oW):
      for c in range(iC):
        for u in range(kH):
          for v in range(kW):
            t1[i,j,c,u,v] = I[c,i+u,j+v]
  R = iC * kH * kW
  S = oH * oW
  t2 = t1.reshape(S, R)
  t3 = K.reshape(oC,R).transpose()

  O = np.matmul(t2, t3)
  O = O.reshape(oH, oW, oC).transpose(2, 0, 1)
  return O

I = np.random.randn(3, 32, 32)
K = np.random.randn(3, 3, 3, 3)

O = conv2d(I, K)
O_ = conv2d_im2col(I, K)
print(np.allclose(O, O_))
```
